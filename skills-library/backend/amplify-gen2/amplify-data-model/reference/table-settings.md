# Table settings: TTL and streams

Model tables are generated by the data construct; tune them in `backend.ts` through the L1 escape hatch
`backend.data.resources.cfnResources.amplifyDynamoDbTables['<Model>']`.

## TTL

Declare an integer field holding **epoch seconds** (not an ISO date, not milliseconds) and enable TTL on it:

```ts
// data/resource.ts
Job: a.model({ …, expiresAt: a.integer() })

// backend.ts
backend.data.resources.cfnResources.amplifyDynamoDbTables['Job'].timeToLiveAttribute = {
  attributeName: 'expiresAt',
  enabled: true,
};
```

- The writer sets `expiresAt = Math.floor(Date.now() / 1000) + TTL_SECONDS` (constant with a comment).
- DynamoDB deletes expired items lazily (often within days, not instantly); readers that care must also
  check `expiresAt` themselves.
- Typical use: job/status rows, idempotency records, short-lived caches.

## Streams

```ts
import { StreamViewType } from 'aws-cdk-lib/aws-dynamodb';

backend.data.resources.cfnResources.amplifyDynamoDbTables['Order'].streamSpecification = {
  streamViewType: StreamViewType.NEW_AND_OLD_IMAGES,
};
```

Consume it with an event source mapping (`tables['Order'].tableStreamArn`) configured with
`bisectBatchOnError`, `reportBatchItemFailures` and a bounded `retryAttempts`. Where the mapping and
consumer live decides the stack dependencies — check for cycles (`amplify-deploy`).
