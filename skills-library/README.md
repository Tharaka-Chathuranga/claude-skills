# Claude skills library

Shared [Claude Code skills](https://code.claude.com/docs/en/skills) and subagents, organized by layer and tech stack.
The **Claude Skills** VS Code extension reads this repo, detects what a project uses, and installs only the
matching modules plus what they depend on. Nobody copies skill folders by hand.

## What's inside

| Layer | Modules |
|---|---|
| `core/` (every project) | `quality` (code quality, architecture boundaries, naming, error handling, security, performance), `design` (OOP principles, design patterns, design reviewer agent), `workflow` (quality gate, ratchet, review standards, commits and PRs, code reviewer agent), `playbooks` (fixes for specific check failures) |
| `languages/` | `typescript`, `dart` |
| `frontend/` | `react` (components, feature structure, forms, hooks, performance), `nextjs`, `mui`, `next-intl`, `amplify-client` |
| `backend/` | `aws-lambda` (Lambda rules, LLM functions), `amplify-gen2` (standards, Lambda scaffolder, data model, resolvers, deploy, scaling limits) |
| `data/` | `dynamodb` |
| `testing/` | `jest`, `storybook`, `playwright` |

Also in the repo:

| Folder | What it is |
|---|---|
| `presets/` | Curated module sets for roles, e.g. Amplify backend developer, full-stack Next.js + Amplify |
| `tooling/quality-kit/` | The scripts behind the quality skills (single gate, ratchet). Copy into a project |
| `templates/` | `quality.config.json`, the per-project numbers the quality skills and scripts read |
| `catalog/` | Generated by the build. The extension reads only this |

## How it fits together

- **Layers:** core skills hold the general rules. Language and tech modules add only what is specific to them, and
  link to core skills by name instead of repeating them. Company libraries add company rules on top.
- **Enforcement:** skills tell Claude how to write good code. The quality kit and CI enforce what can be measured.
  Playbook skills explain how to fix each kind of failure.
- **Numbers:** every number lives in the project's `quality.config.json`, not in the skills, so the same skill works for
  teams with different limits.
- **Dependencies:** each module declares what it `requires`. Picking `backend/amplify-gen2` brings in
  Lambda, DynamoDB, TypeScript and the core modules automatically.

## Contributing

1. Read [AUTHORING.md](AUTHORING.md) for how to write skills that trigger reliably and cost few tokens.
2. Read [FORMAT.md](FORMAT.md) for the module layout, `module.json`, agents and presets.
3. Run `node scripts/build-index.mjs`. It fails on broken limits, duplicate names and unknown `requires`, and
   rewrites `catalog/`. Commit the result.

CI runs the same build on every pull request and rebuilds `catalog/` on every push to `main`.

## Releases

Tag releases (`library-v1.0.0`, `library-v1.1.0`, ...). Projects pin a tag in their `.claude/skills.json` source URL and upgrade by
changing it in a pull request, so a library change never reaches a project unexpectedly.

## Sharing

| Audience | Setup | Cost |
|---|---|---|
| Anyone | Public GitHub repo | Free |
| One company, or a few partner companies | Private repo with read access per company; `"auth": "github"` on the source | Free |
| Shared skills plus company-only skills | This repo plus a private repo per company with a `company/<name>` module; the extension reads both | Free |

The source URL is the raw-content base of a branch or tag, for example
`https://raw.githubusercontent.com/Tharaka-Chathuranga/claude-skills/library-v1.0.0/skills-library`.
